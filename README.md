# 曝光灯管寿命与辐照准入台

古法蓝晒底片整理室的扩展：管理 UV 曝光灯管的累计寿命、校准有效期、辐照达标准入，
以及换管复测双签流程。

## 运行

```bash
npm start          # http://localhost:3040
npm test           # 领域规则测试（17 项）
```

数据保存在 `data/exposure-lamp-bench.json`（首次启动自动播种三根示例灯管）。

## 业务规则

- **同一灯管未完成曝光前不得再分配**：灯管有在制曝光时，新准入请求直接冲突驳回
  （`LAMP_BUSY`，409），不建单、不占灯管。
- **整单拒绝且不占灯管**：累计光照 ≥ 800 小时、校准已过期、实测辐照低于工单要求，
  任一命中即整单拒绝；多条原因同时列出，工单留拒绝履历，灯管不被占用。
- **换管复测**：换管后累计时长归零，灯管进入「待复测」，期间不可准入；
  须由**换管人以外的另一人**、**间隔不少于 15 分钟**、**连续两次实测达标**才放行；
  任一次不达标，连续达标次数清零重来。
- **更正重算**：对已放行曝光更正灯管、要求辐照或开灯时刻，旧工单立即失效并冻结为
  **只读**（`frozen`），按新值重新准入判定；重算若被拒绝同样不占灯管。目标灯管被
  占用时冲突驳回，旧单保持有效。
- **存档只读**：已曝光、已拒绝、已失效工单可归档；已归档与已失效记录拒绝一切写操作
  （`RECORD_READONLY`，409）。

## 三个业务模块

代码按模块分置，共用同一份状态与领域规则：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 入口 | `src/entry.js` | 灯管建档、曝光准入申请 |
| 判定 | `src/decision.js` | 完成曝光、换管、换管复测、更正重算 |
| 存档 | `src/archive.js` | 统一列表、灯管履历查询、工单归档 |

核心纯逻辑在 `src/domain.js`（无 HTTP/IO 依赖，可直接单测）；`src/store.js` 负责 JSON
持久化；`server.js` 只做路由分发与错误码映射。前端三列分别对应三个模块，每次写操作后
统一拉取 `GET /api/state`，列表与灯管履历刷新后必然一致。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/lamps` | 灯管建档 |
| POST | `/api/admissions` | 曝光准入（放行占管 / 整单拒绝不占管） |
| POST | `/api/exposures/:id/complete` | 完成曝光，释放灯管并累计时长 |
| POST | `/api/lamps/:id/replace` | 换管：累计归零，进入待复测 |
| POST | `/api/lamps/:id/retest` | 提交复测读数 |
| POST | `/api/exposures/:id/correct` | 更正灯管/辐照/开灯时刻，旧单失效重算 |
| POST | `/api/exposures/:id/archive` | 归档只读 |
| GET | `/api/state` | 灯管列表 + 工单列表（同一数据源） |
| GET | `/api/lamps/:id/history` | 单根灯管完整履历 |
| GET | `/api/exposures/:id` | 工单详情 |

写接口均可在请求体传 `"at": "ISO-8601"` 指定业务时刻（用于复测间隔判定），
缺省取服务器当前时刻。
